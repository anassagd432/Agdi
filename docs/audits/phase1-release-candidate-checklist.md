# Phase 1 release candidate checklist

This checklist does not publish, tag, or upload a release. A candidate is one
commit SHA plus the lockfile that was generated from that tree. Fill the
result column from commands run on that SHA. A blank or failing row blocks
the candidate.

Rows marked "this pass" were measured 2026-09-21/22 on Windows with Node
`v22.22.2` and pnpm `10.32.1`. Rows marked "earlier pass" are carried over from
the previous session and were **not** re-run. The working tree is shared, so a
row's result is only valid for the tree state at the time it was measured.

## Package smoke detail

Command: `node scripts/check-package-artifact-smoke.mjs`. New script, added this
pass. It dry-run packs, scans the file list, then packs for real, extracts the
tarball outside the checkout, and resolves every declared entrypoint inside it.

Three snapshots. The first two are from the reproducibility pass; the third is
after the staging fix, a full build, and a rule repair.

Two of the three original problems are resolved:

1. **Type declarations now resolve.** The missing `.d.ts` files were never a
   declaration-build failure. `tsc` emits to
   `dist/plugin-sdk/src/plugin-sdk/<entry>.d.ts` because `rootDir` is `.`, and
   the flat paths that `package.json#exports` declares are generated by
   `scripts/write-plugin-sdk-entry-dts.ts`, a later `pnpm build` step. That step
   had not run because the build was failing earlier in the chain. After a full
   build, all 274 declared targets exist.
2. **The gate's `node_modules` rule no longer contradicts the packaging policy.**
   `release-check.ts` intentionally allows `dist/extensions/<id>/node_modules/`.
   The smoke gate forbade all `node_modules`, which produced 13213 false
   positives once staging worked. The policy now lives in one module,
   `scripts/lib/pack-path-policy.mjs`, used by both gates. Zero disallowed
   `node_modules` paths remain in the pack.

One problem remains, and it is real rather than a false positive:
`dist/extensions/telegram/node_modules/bottleneck/.env` ships in the artifact.
It contains `REDIS_HOST=127.0.0.1` and `REDIS_PORT=6379` — `bottleneck`'s own
committed defaults, not a credential — but it is a dotenv file inside a
publishable artifact. The rule was left in place rather than narrowed to turn
the gate green; resolving it is a packaging-policy decision. Details in
[Phase 1 package artifact integrity](/audits/phase1-package-artifact-integrity).

Also worth recording: `.npmignore` contains `**/node_modules/`, but it cannot
enforce that. `package.json#files` lists `dist/`, and npm does not let
`.npmignore` exclude paths that `files` already included.

Packing still has no build hook: there is no `prepack`, `prepare`, or
`prepublishOnly` script, so `npm pack` alone never produces a working artifact.

  holder, and A2UI Apache notice. Owner: Anass. Expiry: unset. Legal review.
- Critical and high production advisories. Owner: Anass. Expiry: unset.
  Another workstream landed overrides for `hono`, `tar`, `ws`, and `form-data`
  at 02:17 during this pass, which may reduce the count. `pnpm audit --prod` was
  **not** re-run, so the 2 critical / 21 high figures above are the last
  measured values and may now be stale in either direction.
- The allowlist duplication itself. `onlyBuiltDependencies` and
  `ignoredBuiltDependencies` are still declared in both `package.json` and
  `pnpm-workspace.yaml`. Only the workspace file takes effect. The two currently
  agree, but nothing enforces that. Owner: unset. The right end state is one
  source of truth; `package.json` is out of scope for the reproducibility pass.
- Stale allowlist entries with no lockfile presence: `@tloncorp/api`,
  `authenticate-pam`, `@discordjs/opus`. Owner: unset.
- `pendingBuilds` is never drained by a frozen install. Owner: unset. Blocks any
  claim that a clean checkout builds its native dependencies.
- Lockfile churn. `pnpm-lock.yaml` and `package.json` changed under a running
  verification pass. Any candidate must pin both a SHA and a lockfile hash, and
  re-check the hash immediately before signing off.
- `dist/extensions/telegram/node_modules/bottleneck/.env` ships in the artifact.
  A third-party package's own committed Redis defaults, not a credential, but
  still a dotenv file inside the publishable tarball. Owner: unset. Blocks the
  package smoke gate.
- `release:check` cannot complete. Four of its seven steps fail, so it stops
  before `release-check.ts` is reached: `check:public-branding` (exit 1),
  `config:docs:check` (exit 1, config baseline drift), `plugin-sdk:api:check`
  (exit 1, Plugin SDK API baseline drift), and `release-check.ts` itself
  (exit 1, `ENOENT` on `appcast.xml`). `plugin-sdk:check-exports` and `ui:build`
  both pass. Owner: unset.
- **`pnpm build` has never completed on a re-run.** Two distinct problems:
  - **Slow, environmental, not a repo defect.** This host charges ~29ms to
    _create_ any file outside Temp, against 0.9ms to overwrite one and 0.25ms to
    create one in Temp — a ~78x penalty that holds outside the repository too and
    accounts for `reify:unpack`'s 112.8s (measured with `npm install --timing`).
    That is why staging costs 131s per plugin here against 15-20s elsewhere. The
    staging script needs no change.
  - **A hang that is unresolved.** Four attempts to run the staging path did not
    complete; the last ran 33m22s and was idle for over 30 minutes while staging
    slack (zero `dist/` writes, zero slack `node_modules` writes in 30 min, zero
    npm cache writes in 6 min, frozen staged count). **It did not reproduce in
    isolation** — slack's install completed normally in 131s alone — so the cause
    is unidentified. Eliminated: repo `.npmrc`, an npm `workspaces` declaration,
    the host bulk-delete guard, stale npm cache locks.

  Owner: unset. **Highest-priority blocker.**

- **`dist/` is left partially built** by the killed runs: 14 of 86 extension
  manifests, no `dist/control-ui/index.html`, 14 of 134 flat `plugin-sdk` entry
  shims. `dist/` is gitignored, so no tracked file is affected. Owner: whoever
  resolves the staging hang.

## Verdict

A candidate cannot ship from this tree. The host-rename leak in bundled plugin
staging is fixed, and every declared entrypoint in the package artifact resolves,
so two of the three original artifact problems are closed. But `pnpm build` now
**fails**: it exited 0 once and then hung on two later runs, the last idle for
over 30 minutes mid-staging. The package smoke gate still fails on one real
count — `dist/extensions/telegram/node_modules/bottleneck/.env`
ships — and
`release:check` cannot complete in this checkout: four of its seven steps fail
(`check:public-branding`, `config:docs:check`, `plugin-sdk:api:check`, and
`release-check.ts` on the missing `appcast.xml`). `format:check` and `test:unit`
still end in `|| true`;
`build:plugin-sdk:dts` and `typecheck` no longer do.

Windows frozen-install determinism is proven on both lockfile revisions;
cross-platform reproducibility is not. The script-enabled path is only proven
not to execute scripts — it is not proven to build.
