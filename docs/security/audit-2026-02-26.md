### Low (1)

#### hono <4.11.10 — Timing comparison in basicAuth/bearerAuth

- **Path**: `agdi → @buape/carbon → @hono/node-server → hono 4.11.9`
- **Classification**: ⚠️ **Prod-reachable** via Discord integration (`@buape/carbon`).
- **Risk**: Low. The timing attack requires network-level precision and is against the Discord bot's internal auth, not user-facing auth. The gateway's own auth uses a separate implementation with proper comparison.
- **Mitigation**: No fix available without upgrading `@buape/carbon`, which may introduce breaking changes. Accepted risk — timing attacks on Discord bot auth tokens are impractical.

## Accepted Risks

1. **Matrix extension chain** (request, ajv, ip-address, esbuild): All vulnerabilities are isolated to the optional Matrix channel extension. This extension is **not loaded by default** and requires explicit `channels.matrix` configuration. Users who don't enable Matrix are not affected.

2. **hono timing hardening**: The vulnerable timing comparison is in hono's `basicAuth`/`bearerAuth` middleware which is used internally by `@buape/carbon` for Discord bot communication. This code path handles Discord-to-bot authentication, not user-facing gateway auth. The gateway's own auth implementation uses a separate, hardened comparison.

3. **rollup path traversal**: Dev-only dependency. Only runs during `pnpm build` on developer machines, never in production runtime.

## Security Configuration Verified

### Rate Limiting

- **Implementation**: Per-IP with `resolveGatewayClientIp()` in `src/gateway/net.ts`
- **Proxy safety**: Only trusts `X-Forwarded-For` when `remoteAddr` matches explicit `trustedProxies` allowlist
- **Limits**: 20 failures per 60-second window, per client key, with 2048-entry tracking cap
- **Not bypassable**: Spoofed `X-Forwarded-For` headers are ignored unless the request comes from a configured trusted proxy IP

### Content Security Policy

```
default-src 'self';
base-uri 'none';
object-src 'none';
frame-ancestors 'none';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: https:;
font-src 'self';
connect-src 'self' ws: wss:
```

- ✅ `script-src 'self'` — No unsafe-eval, no unsafe-inline for scripts
- ⚠️ `style-src 'unsafe-inline'` — Required for Lit/Web Components inline style attributes. Standard practice for Shadow DOM frameworks. CSS injection risk is minimal (no script execution).
- ✅ `connect-src 'self' ws: wss:` — WebSocket origins are permissive to support variable gateway bind hosts (localhost, LAN IPs). WebSocket auth is enforced at the protocol level (token/password handshake), not via origin restrictions.
- ✅ `frame-ancestors 'none'` — Prevents clickjacking entirely.
